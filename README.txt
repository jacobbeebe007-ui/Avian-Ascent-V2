Avian Ascent Refactored Project

Structure
- index.html (loads ./js/avian-game.bundle.js — the prebuilt classic shell)
- css/main.css, css/sprites.css, css/battle.css, css/shop.css, css/ui.css
- js/bootstrap/load-order.json (canonical ordered list of source scripts)
- js/avian-game.bundle.js (generated by scripts/build-bundle.js — gitignored)
- js/data/ailments.js (leaf data; first entry in the manifest)
- js/data/ability_passive_upgrade_pack.js, js/data/ability_family_tree.js, js/data/story_enemy_registry.js
- js/world/overworld_bridge.js
- js/core/game.js (large gameplay core)
- js/data/content.js
- js/systems/systems.js, js/systems/shop.js
- js/ui/ui.js, js/ui/sprites.js
- scripts/build-bundle.js (no-deps Node concat — works without npm install)
- vite.config.mjs (optional Vite dev server: live concat + minified prod build)
- sw.js (offline shell, precaches the bundle)

Notes
- Source scripts share one browser global realm; they are concatenated WITHOUT an outer IIFE so top-level `function foo()` stays on window for inline onclick handlers in index.html.
- `npm test` parses the source files under js/ (e.g. js/core/game.js), not the emitted bundle.

Quick play (no toolchain — file:// works)
1. Run once after pulling, and after editing any source file: `node scripts/build-bundle.js`
2. Double-click index.html, or serve the repo root with any static server.
   - If you forget step 1 you'll get an alert: "js/avian-game.bundle.js is missing".

Live dev (Vite — auto-reload, no manual rebuild)
- One-time: `npm install`
- Run: `npm run dev` and open the printed URL (default http://localhost:5173).
- The Vite middleware intercepts /js/avian-game.bundle.js and serves a fresh concat from the manifest on every request, so edits show on reload.

Background bundler (no Vite)
- `npm run bundle:watch` rebuilds js/avian-game.bundle.js whenever a manifest source file changes; refresh the page to see edits.

Production build
- `npm run build` writes dist/ with a minified js/avian-game.bundle.js, copied CSS/icons/manifest, and sw.js.
- Preview the built output: `npm run preview` (binds 0.0.0.0).

Mobile on same Wi-Fi
- After `node scripts/build-bundle.js`, run `npm run preview:static` (or any static server) and open `http://<LAN-ip>:<port>`.
- Or use `npm run dev -- --host 0.0.0.0`.

Merge/CI quick check
- `npm test` before pushing/PR (needs Node.js).
- Validates JS parse and verifies every sprite path in CSS points to an existing file.


If GitHub says the merge is too complex
- This usually means the PR is very large or has overlapping edits with the base branch.
- Fix it locally instead of the web editor:
  1) `git fetch origin`
  2) `git checkout <your-branch>`
  3) `git rebase origin/main`  (or `git merge origin/main`)
  4) Resolve conflicts, then run `npm test`
  5) `git push --force-with-lease` (for rebase) or `git push` (for merge)
- If the PR is still too large, split it into smaller PRs (sprites/paths, gameplay, UI) so GitHub can evaluate checks and diffs reliably.

World Creator (Build Nest)
- War Room hotspot “Build Nest” (unlock code `buildnest`) opens World Creator (subtitle: Build Nest).
- Hierarchy: World pack → Maps (main + nested) → Locations.
- Location kinds: Spawn, Stage, Boss, Bonus, Shop, Map gate, Return, Overworld gate, Decor, UI button.
- Library: new world from a template (blank, story campaign, linear 5-stage, hub with 2 maps, single-fight test), open/delete drafts, import a JSON pack.
- Workspace: world tree (left; add/duplicate/delete nested maps), canvas with a Place palette, inspector (right). Pick a kind, then click the map.
- Export writes schema v3 JSON. Data-URL backgrounds are stored under `assets` as `asset:<id>` references. Import accepts v2 or v3 and reports blocking errors.
- Playtest / Use on next run is blocked until the start map has a Spawn, the pack has a fight, a background, and map gates point at real maps. Save draft still works with those errors.
- Custom maps honor authored encounter size (1–5 enemies). The shipping Blackstone story stays single-enemy unless you play a custom pack.
- Promote a pack into the shipping story map: `node scripts/import-story-map.mjs path/to/export.json` (nested maps are kept).

Android (Capacitor)
- Requirements: Node.js, Android Studio, and an Android SDK/JDK supported by the installed Capacitor version.
- Install dependencies with `npm install`.
- Create the production web output and native project once with `npm run android:add`.
- After changing the game, copy a fresh production build into Android with `npm run android:sync`.
- Open the generated `android/` project in Android Studio with `npm run android:open` to run, sign, and publish the app.
- The permanent Android application ID is `com.jacobbeebe.avianascent`; Capacitor serves the relative-path Vite build from `dist/`.
- The generated `android/` project should be committed after `android:add` has run successfully so native settings and icons can be maintained in source control.
